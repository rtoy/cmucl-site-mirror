**Snapshot 2010-12**
: Some of the important changes are listed below. See the [release notes](https://cmucl.org/downloads/snapshots/2010/11/release-20c.txt)
  for more details.

  - ASDF2 updated to version 2.010.
  - On x86, `REALPART` and `IMAGPART` no longer incorrectly returns 0 instead of
    the correct part of a complex number in some situations.
  - The command line parser now correctly handles the case where `--` is the
    first command option.
  - `build.sh` was accidentally loading the site-init file, but it shouldn't.
  - On sparc, the vops to add a float to a complex were broken, resulting in a
    complex number with the float as realpart and garbage for the imaginary part.
    This is now fixed.
  - `XLIB::GET-BEST-AUTHORIZATION` will now return authorization data if the
    protocol is `:local`, if the xauth file contains just `localhost/unix:0`.
  - `FORMAT` signals a warning if `~:;` is used inside `~:[`.
  - `SET-SYSTEM-EXTERNAL-FORMAT` was not actually setting the filename encoding
    if given.

**20b patch 000**
: A critical bug in `REALPART` and `IMAGPART` has been fixed in the 2010-11
  snapshot. A [patch](https://cmucl.org/downloads/release/20b/patches/cmucl-20b-patch-000.tar.gz)
  is provided now to fix this issue in the 20b release.
  [Installation]({{ '/install.html' | relative_url }}) instructions are available.

**2010-11 snapshot**
: Some of the important changes are listed below. See the [release notes](https://cmucl.org/downloads/snapshots/2010/11/release-20c.txt)
  for more details.

  - Update to Unicode 5.2.0.
  - Support for character name completion for use with Slime.
  - `COMPILE-FILE` accepts a `:DECODING-ERROR` argument that indicates how to
    handle decoding errors when reading the file.
  - `RUN-PROGRAM` accepts `:EXTERNAL-FORMAT` parameter to specify the external
    format for streams that are created.
  - `READ-CHAR` signals errors on non-character streams. `READ-BYTE` signals
    errors on character streams. Both will work if the stream is a
    `binary-text-stream`.
  - `REALPART` and `IMAGPART` no longer return 0 instead of the correct part of
    a complex number in some situations.

**20b released**
: CMUCL 20b has been released. For information on the changes, we refer the
  reader to the [20b release notes](https://cmucl.org/news/release-20b.txt).

**2010-09 snapshot and 20b prerelease 2**
: CMUCL 20b prerelease 2 has been released, in preparation for the upcoming 20b
  release. Therefore there will not be a 2010-09 snapshot.

  - It is possible to hash NaNs (IEEE Not-a-Number).
  - For SSE2 builds, `=` no longer signals an error if one operand is NaN.
  - For SSE2 builds, `SIGCONTEXT-FLOAT-REGISTER` returned the wrong value for
    single-floats.
  - Trac issue #36: `FILE-POSITION` returns the correct value for UTF16 and
    UTF32 when there is a BOM at the beginning of the file.

**2010-08 snapshot and 20b prerelease 1**
: CMUCL 20b prerelease 1 has been released, in preparation for the upcoming 20b
  release. Therefore there will not be a 2010-08 snapshot.

  - Error handling has been added to external formats. The user can specify how
    errors are handled by using the `:DECODING-ERROR` and `:ENCODING-ERROR`
    parameters to `OPEN`.
  - Add `EXT:LIST-ALL-EXTERNAL-FORMATS` to list all known external formats and
    their aliases.
  - Add `EXT:DESCRIBE-EXTERNAL-FORMAT` to print a description of the specified
    external format.
  - The sparc port now supports the `:executable` feature.
  - The Mac OS X port now supports the `:executable` feature.
  - A critical bug in the fast unicode stream buffering routine has been fixed.
  - UTF-8 correctly catches overlong sequences now.
  - Some GC improvements for sparc and ppc.
  - With SSE2, the imaginary part of a `(complex single-float)` is now returned
    correctly.

**2010-07 snapshot**
: - `DELETE-FILE`, `ENSURE-DIRECTORIES-EXIST`, `FILE-AUTHOR`, `FILE-WRITE-DATE`,
    and `OPEN` now merge the given pathname with `*DEFAULT-PATHNAME-DEFAULTS*`
    as required by CLHS sec 19.2.3.
  - When printing out argument values in the debugger and also during `TRACE`,
    the incorrect values were returned for the SSE2 core. This is fixed now.

**2010-06 snapshot**
: - ASDF2 and MK-DEFSYS have been added as contrib modules. Use `(require :asdf)`
    or `(require :defsystem)` to load these.
  - A new switch `-help` has been added. This prints out a brief summary of the
    available command line switches and exits. You may also use `--help`.
  - The GCD of positive integers sometimes returned a negative result. This is fixed.

**2010-05 snapshot**
: - Source information (file) for defstructs and deftypes is now provided.
    `DESCRIBE` will print out the name of the file where the
    defstruct/deftype was defined.
  - `WITH-STANDARD-IO-SYNTAX` uses the standard pprint dispatch table now
    instead of the current table.
  - `PRINC-TO-STRING` binds `*PRINT-READABLY*` to `NIL` as required.
  - `DEFCLASS` signals an error if the class name already names a `DECLARATION`.
  - `MAC` is an alias for the `CR` composing external format.
  - [Trac #39](http://trac.common-lisp.net/cmucl/ticket/39): the reader macros
    are no longer installed by default. Use `(intl:install)` to install them.

**2010-04 snapshot**
: - Support for internalization/localization added. Messages from CMUCL can be
    translated.
  - `COMPILE` will update the macro-function if the specified name is a macro.
  - CMUCL now signals a cerror when attempting to redefine a slot accessor via
    `DEFUN` or `COMPILE`.
  - An issue with SSE2 and GC hooks has been fixed.

**2010-03 snapshot**
: - `FROUND` is much faster for single and double float numbers.
  - CMUCL no longer segfaults on Linux when running on a kernel without
    `COMPAT_BRK`.
  - `GET-MACRO-CHARACTER` would return the wrong second value because
    `*READTABLE*` was always being used instead of the specified readtable.
  - A critical bug in SSE2 support has been fixed. Multiplying a complex
    single-float by a single-float produced the wrong result.

**2010-02**
: - Some issues with `FILE-POSITION` on unicode builds have been fixed.
  - The error-output and trace-file files are now opened using the same external
    format as specified in `COMPILE-FILE`.
  - The debugger now opens files using the same external format as used to
    compile them.

**2010-01-04**
: Experimental support for static arrays has been added. These are allocated in
  foreign (malloc) space and are never moved by GC. They are, however, properly
  garbage collected. To create an array, use `MAKE-ARRAY` with `:ALLOCATION
  :MALLOC`.
